# Druse 0.1.0 — primera beta

Fecha: 2026-08-12 · Plataforma publicada: **Windows x64**

Es la primera versión que se puede instalar y usar de principio a fin. El número
`0.1.0` ya dice lo que es: una beta. Se publica para usarla de verdad contra
bases reales y descubrir lo que solo aparece usándola.

---

## Qué trae

| Área | Qué se puede hacer |
| --- | --- |
| Motores | **PostgreSQL 12–18**, **SQL Server 2016–2022** y **MySQL 8.0+ / MariaDB** |
| Conexiones | Crear, probar, guardar y reabrir perfiles; color por entorno; marcar solo lectura |
| Explorador | Bases, esquemas, tablas, vistas, funciones, procedimientos y columnas, con carga perezosa |
| Editor | Monaco con resaltado, formateo por dialecto, autocompletado de esquema y varias pestañas |
| Ejecución | Consulta completa o solo la selección, límite de filas, tiempo de espera y cancelación |
| Resultados | Varios conjuntos, filtros locales, copiar celdas y filas, nulos distinguidos |
| Exportación | CSV (RFC 4180, codificación elegible) y XLSX |
| Historial | Persistente y filtrable, incluidas las ejecuciones fallidas |
| Escritorio | Instalador NSIS, MSI y ZIP portable; **no requiere .NET ni Node.js** |

## Qué se ha comprobado, y con qué números

- **24 pruebas contractuales idénticas** superadas por los tres motores —72 en
  total—, sin excepciones por motor. MariaDB 11.4 supera las mismas 24 con el
  proveedor de MySQL.
- Suite completa: **219 pruebas de backend** y **78 de frontend**.
- Contra MySQL 8.4 con una base de 9 630 documentos y 1 284 usuarios:
  metadatos en **~5 ms**, `SELECT` de 500 filas en **~26 ms**, exportación de
  las **9 630 filas completas a CSV en 0,06 s**.
- La memoria del proceso **no crece con el tamaño del resultado**: 44 MB antes y
  42 MB después de tres exportaciones completas seguidas, porque exportar
  recorre el resultado sin materializarlo.
- Cancelación real de una consulta en curso: cortada a los **2,8 s** de un
  `SLEEP(30)`.
- `DELETE` sin filtro rechazado con **409** y el riesgo explicado, también por la
  vía de exportación.

## Lo que esta beta todavía no garantiza

Se dice antes de que se descubra por sorpresa:

- **El ciclo de instalación, actualización y desinstalación no se ha validado en
  un equipo limpio.** Los instaladores se generan y la aplicación arranca, pero
  falta probarlo en una máquina sin herramientas de desarrollo.
- **Solo hay artefactos de Windows x64.** El código compila para Linux y macOS y
  la integración continua lo verifica, pero no se han generado instaladores para
  esas plataformas.
- **No hay actualizador automático.** Instalar una versión nueva es volver a
  ejecutar el instalador.
- **Sin túneles SSH, sin autenticación integrada de Windows para SQL Server y sin
  edición directa de filas.** Están en el backlog, por ese orden de prioridad.
- **El aviso de instrucciones destructivas es una ayuda visual**, no un
  sustituto de los permisos del servidor. Una conexión con permisos de escritura
  puede escribir.
- La estimación de filas del explorador es aproximada a propósito: sale de las
  estadísticas del motor (`reltuples`, `dm_db_partition_stats`, `TABLE_ROWS`) y
  puede desviarse. Contar de verdad haría inservible el árbol en una base grande.

## Instalación

Descarga uno de los tres artefactos y ejecútalo:

| Artefacto | Cuándo |
| --- | --- |
| `Druse_0.1.0_x64-setup.exe` (NSIS) | Instalación normal |
| `Druse_0.1.0_x64_en-US.msi` | Despliegue por directiva de grupo |
| `Druse-0.1.0-win-x64-portable.zip` | Sin instalar, desde una carpeta cualquiera |

En modo portable la configuración **sigue guardándose en el directorio del
usuario**, no junto al ejecutable. Copiar la carpeta a otro equipo no lleva las
conexiones con ella.

## Dónde quedan tus datos

| Qué | Dónde |
| --- | --- |
| Perfiles, historial y preferencias | `%APPDATA%\Druse\druse.db` |
| Contraseñas | Administrador de credenciales de Windows |
| Puerto y token de la API local | `%APPDATA%\Druse\endpoint.json`, se reescribe en cada arranque |

**Ningún archivo local guarda contraseñas legibles.** Si el sistema no ofrece un
almacén seguro, Druse no la guarda y la pide en cada conexión, diciéndolo en la
interfaz: cifrar un archivo con una clave que está en el mismo disco sería
seguridad aparente. Ver [ADR 0004](../decisions/0004-almacenamiento-de-secretos-y-token-local.md).

La API local escucha **solo en loopback y exige un token**. Sin él, cualquier
proceso de la máquina podría abrir sesiones contra tus bases de datos.

## Qué ayuda más al reportar un fallo

El motor y su versión, el SQL que lo provocó —sin datos reales— y lo que
apareció en el panel de mensajes. Si es un fallo de conexión, el texto del error
tal cual: ya sale saneado, nunca lleva la contraseña dentro.
